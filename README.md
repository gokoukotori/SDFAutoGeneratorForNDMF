# SDF Auto Generator For NDMF

lilToon の影マスクタイプ「SDF」用のテクスチャ（`_ShadowStrengthMask`）を、アバターのメッシュから自動生成し、NDMF のビルド時に非破壊で適用するツールです。市販の SDF テクスチャを買ったり、アバターごとに手作業で作ったりする代わりに使えます。結果は NDMF プレビューでシーン上に確認できます。元のマテリアル・メッシュ・プレハブは書き換えません。

## 必要環境

- Unity 2022.3 または Unity 6（6000.0.67f1・Direct3D 11・VRChat SDK 3.11.0-beta.1・NDMF 1.15.1・Modular Avatar 1.19.0 で動作を確認。生成方法を作り直してからは、Unity 2022.3 での動作は未確認です）
- GPU（生成にグラフィックス処理を使います）
- NDMF 1.15.0 以上
- lilToon 2.x（2.4.1 で動作を確認）
- Modular Avatar と AO Material Editor は必須ではありません。あれば順序を合わせて共存します。

## 導入

- このフォルダ（`com.gokoukotori.sdf-auto-generator.ndmf`）をプロジェクトの `Packages/` に置く。
- または、Unity の Package Manager の「Add package from git URL」で、公開先リポジトリの URL を指定する。例: `https://github.com/<owner>/<repository>.git?path=Packages/com.gokoukotori.sdf-auto-generator.ndmf`（`<owner>/<repository>` は**プレースホルダー**です。実際に公開されているリポジトリの URL に置き換えてください）。

`package.json` に依存関係は書いていません。NDMF と lilToon は別途導入してください。

## 使い方

1. アバタールート（VRC Avatar Descriptor があるオブジェクト）に `SDF Auto Generator` コンポーネントを追加する（メニューは Add Component > Gokoukotori > SDF Auto Generator）。
2. 「対象」を選ぶ。「指定したマテリアル」なら「対象マテリアル」に lilToon のマテリアルを入れる。「すべてのマテリアル」ならアバター内の対象条件を満たすものすべて。
3. NDMF プレビューで確認する。必要なら「光の高さ」などの値を調整する。
4. そのままアップロード（またはビルド）する。ビルド時に SDF テクスチャが生成され、適用されます。

コンポーネントはアバタールートにだけ置けます。ルート以外にあるものは警告を出して無視されます。

### 対象になるマテリアル

lilToon のマテリアルで、影が有効（`_UseShadow` がオン）なものだけが対象です。AO Material Editor などが適用された後の値で判定します。lilToon の Gem シェーダー（影の処理が無い）は対象外です。Renderer のスロットのほか、アニメーションでのマテリアル差し替えや Modular Avatar の Material Swap による差し替え先にも SDF が適用されます。

「指定したマテリアル」のときは、アニメーションや MA Material Swap で差し替えられるマテリアルも、「対象マテリアル」に入れたものだけが対象です。差し替え先にも SDF を使いたいときは、差し替え先のマテリアルも一覧に入れてください。

### 生成されるテクスチャ

テクスチャは「Renderer × マテリアル」ごとに 1 枚作ります（同じマテリアルでも Renderer が違えば別のテクスチャと別の複製になります）。1 枚の大きさは 1024 の BC7 で約 1.3 MiB（2048 で約 5.3 MiB）です。「すべてのマテリアル」では対象のマテリアルの数だけ増えるので、アバターのサイズに注意してください。

## 設定

| 項目 | 既定値 | 意味 |
|---|---|---|
| 対象 | 指定したマテリアル | 「指定したマテリアル」か「すべてのマテリアル」 |
| 対象マテリアル | 空 | 「指定」のときだけ表示。SDF を適用するマテリアル |
| 光の高さ（°） | 15 | 光が水平からどれだけ上から当たる前提で影を作るか。大きいほど、あご下や下向きの面が早く暗くなる。テクスチャに焼き込まれる。0〜89 |
| 法線のなめらかさ | 5 | 法線をならす回数。大きいほど影がなめらかになり、細部は減る。0 でならさない。0〜50 |
| 落ち影の届く距離（m） | 0.03 | これより遠い所からの落ち影は入れない。0 で落ち影なし。0 以上 |
| テクスチャ解像度 | 1024 | 生成するテクスチャの一辺。512 / 1024 / 2048 から選ぶ。プレビューは常に 512 |

既定値（光の高さ 15°・なめらかさ 5・距離 0.03 m）は、検証用アバター（Chiffon）と市販テクスチャ 1 つから決めたものです。アバターによっては調整が必要です。

光の高さ・法線のなめらかさ・落ち影の届く距離は、入力を確定したとき（Enter を押すか、欄から離れたとき）に反映され、範囲の外の値は範囲内に丸めます。

### 作り方

メッシュに実際に光を当てて、角度ごとの明暗を求め、1 枚にまとめます。

- 光の水平角を 180 通り（0°〜180°）に分け、−X 側と +X 側それぞれについて、各角度で面が明るいか暗いかを調べます。法線の上下成分と、設定した光の高さを含めます。
- **落ち影**: 同じマテリアルの中だけで影を落とします。左右で UV を共有する部分は影を落としません（テクセルより小さい三角形も、その位置のテクセルで判定します）。「落ち影の届く距離」より遠い遮蔽物の影は入れません。
- **値**: 全角度のうち明るかった割合です。明るさが θ* まで続き、その後ずっと暗いテクセルなら、値は θ*/180° です。角度に比例し、上下の頭打ちはしません。
- **後ろ向きの面**（耳の裏、後頭部など）: lilToon の SDF は「ある角度まで明るく、その後は暗い」しか表せません。前から当てると暗く、後ろ寄りから当てると明るい面は、B を上げて通常の影にします。法線と光の高さから決める規則で、境目はなめらかに混ぜます。
- **法線のなめらかさ**: 位置で溶接した頂点の法線を、生成対象の三角形の中だけでならします。開いたメッシュの縁（1 枚の三角形だけが使う辺）の頂点は自分の法線を保ち、首の継ぎ目の値が不連続になるのを防ぎます。同じ位置でも法線の向きが逆の頂点（表裏の面が同じ頂点位置を持つ両面メッシュの表と裏）は溶接せず、表と裏を別々にならします。

### 影の境界との関係

SDF はマテリアルの影の設定（`_ShadowBorder`、影2・影3 の境界など）を参照せずに作ります。影の境界は、SDF を使った見た目を見ながら決める値です。それを読んで焼き込むと、境界を変えてもテクスチャ側で打ち消され、見た目が変わらなくなるためです。同じ理由で、影の強さ・ぼかし・境界などの影の設定は書き換えません。マテリアル（または AO Material Editor）で調整してください。SDF では、ぼかしを小さめ（0〜0.1 程度）にすると影の形がはっきり出ます。

テクスチャの値は角度に比例します（値が大きいほど、影が出始める光の角度が大きい）。lilToon は、マテリアルの影の境界に応じて、影が出るタイミングをずらします。境界が高いと影が早く出て、低いと遅く出ます。lilToon は 1 枚の SDF を影1・影2・影3 で共有するので、影2・影3 もそれぞれの境界で同じようにずれます。手描きの SDF テクスチャと同じ振る舞いです。

lilToon の SDF では、影1〜3 のそれぞれが表せる角度の幅が、その影の境界で決まります（例: 境界 0.5 なら 60°〜120°、0.717 なら 21°〜94°）。幅の外では、テクスチャによらず常に明るいか常に暗くなります。

## 書き換えるプロパティ

ツールが対象マテリアルに書くのは次のものだけです。マテリアルは複製してから書き換えます。

- `_ShadowMaskType` = 2（SDF）
- `_ShadowStrengthMask` = 生成したテクスチャ

影の設定（強さ・ぼかし・境界、影2・影3 の設定など）は読まず、書き換えもしません（上の「影の境界との関係」）。`_ShadowFlatBlur` など、他のプロパティも変えません。

生成テクスチャは、R = 光源がメッシュの −X 側にあるときの明るさ、G = +X 側のとき、B = 通常の影との混ぜ具合（左右で UV を共有する部分は 1 で通常の影になる。後ろ向きの面は 0〜1 でなめらかに混ぜる。それ以外は 0）、A = 1 です。ビルドでは BC7 で圧縮し、リニア・ミップマップあり・Streaming Mip Maps 有効・Read/Write 無効で作ります。

## 実行タイミングと他ツールとの関係

NDMF の Transforming フェーズで、AO Material Editor と Modular Avatar の後、Modular Avatar の後段処理（late-transform-stages）の前に実行されます。

TexTransTool との順序は指定していません。TexTransTool と Light Limit Changer を両方入れると TexTransTool が Modular Avatar より前に固定されるため、その環境では本ツールは TexTransTool の後に動きます。

### AO Material Editor との関係

AO Material Editor がマスクタイプ・マスクを設定していても、本ツールの値が優先されます。影の強さ・ぼかし・境界など、それ以外の値は AO Material Editor で設定したものがそのまま残ります。

## 警告が出る場合

警告は NDMF のエラーレポート（ウィンドウ）に出ます。警告が 1 つでもあると、ビルドやプレイモードに入るたびにそのウィンドウが開きます。

- コンポーネントがアバタールートにない（無視されます）
- 対象が 1 つもない
- Renderer の基準ボーン（rootBone。なければ Renderer の Transform）の前方が、アバターの前方から 30° を超えてずれている、または基準ボーンの上方向（+Y）がアバターの上方向から 30° を超えて傾いている（前後・左右に倒れている）（その Renderer は対象から外れます。SDF は基準ボーンのローカル X が水平で +Z が前方であることを前提にするため）
- Renderer の基準ボーンが Neck / Head（またはその子孫）にある（処理は続行します。顔の影が頭に追従し、体と基準が異なります）
- マテリアルの UV に描画範囲がない（UV0 が無い、UV の三角形がすべてつぶれている、三角形以外のメッシュなど。そのマテリアルには SDF を適用しません）
- マテリアルがメインテクスチャの UV スクロール・回転（`_MainTex_ScrollRotate`）や裏面 UV シフト（`_ShiftBackfaceUV`）を使っている（このツールはそれらを再現できないため、そのマテリアルには SDF を適用しません）
- マテリアルの UV のうち 30% を超える部分が左右で共有されている
- マテリアルの SDF を生成できなかった（UV が 64 タイルを超える範囲に広がっている、UV に有限でない値（NaN・無限大）がある、GPU での生成に失敗した（シェーダーがその GPU・グラフィックス API で使えない、何も描けなかったなど）。そのマテリアルには SDF を適用せず、ほかのマテリアルは続けて処理します。元の例外は Unity のコンソールにも出します。NDMF プレビューでは、ウィンドウではなくコンソールに警告を出し、そのスロットには表示しません）

次の場合は、NDMF のウィンドウではなく Unity のコンソールにだけ警告を出します（ユーザーが直せない場合が多いため）。

- 対象マテリアルがアニメーションで、アバターに存在しないパスの Renderer に差し替えられている（その差し替えには SDF を適用しません）

## 既知の制限

- 首を振っても、顔の影は追従しません（基準ボーンの向きのままです）。ただし、顔メッシュの基準ボーンが元から Neck / Head にあるアバターでは追従します（その場合は警告を出します）。顔だけ基準が体と異なると、場面によって顔だけ明るくなり違和感が出るため、基準ボーンの付け替えはしません。
- 「すべてのマテリアル」で体や服に使うと、腕や脚を動かしても影が変わりません。
- 左右で UV を共有する部分は、通常の影になります。
- 上からの光で Y 方向のブレンドがどう効くかは未検証です。
- TexTransTool、Light Limit Changer、AAO（Avatar Optimizer）との組み合わせは未検証です。
- 既定値（光の高さ・なめらかさ）は、Chiffon と市販テクスチャ 1 つから決めたものです。
- NDMF の Transforming フェーズより後に動くツール（VRCFury など）が追加するアニメーションやマテリアルの差し替えには、SDF は適用されません。
- 生成に GPU が必要です。
- 落ち影は、同じマテリアルの中だけで落ちます。顔と体が別のマテリアル（別の Renderer）のとき、あごの影は首の継ぎ目で切れます。
- 光の高さはテクスチャに焼き込まれます。光の高さを変えるには、テクスチャを作り直します。
- 小さな不具合が残っています。落ち影による段になったまだらと、目・額のまわりの細い明るい線、法線の平滑化による、顔の中央線上（光がおよそ 90° のとき）の少しギザギザした線です。今後の改善として扱います。
- NDMF プレビューは元のメッシュから生成します。ビルド中にメッシュを変えるもの（MA Shape Changer の削除、メッシュの削除ツールなど）があると、プレビューとビルド結果が少し違うことがあります。
- NDMF プレビューは、基準ボーンに SkinnedMeshRenderer の祖先がないメッシュ（まれに BakeMesh で代用する場合）では、ポーズの変更だけでは作り直されません。
- 元の Renderer のマテリアルが対象の条件（lilToon・影が有効）を満たさず、別のプレビューフィルタ（AO Material Editor、MA Material Swap など）によって初めて条件を満たすスロットは、プレビューには反映されません（ビルドでは適用されます）。
- 「指定したマテリアル」のプレビューでは、元のマテリアルとプレビュー上で差し替えられたマテリアル（MA Material Swap など）のどちらかが一覧にあれば SDF を表示します。そのため、一覧に入れた元のマテリアルが既定でオンの Material Swap で一覧に無いマテリアルに差し替えられる場合などに、プレビューには表示されてもビルドでは適用されないことがあります。
